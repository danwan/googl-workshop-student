# P-17 Review Package: Conflicting Coast Site Application

- Source system: simulated intake review
- Document ID: SCE-INBOX-003
- Version: 1.0
- Applicant: TechBond Service, Coast Site
- Status: conflict review required

This dossier contains two differently labeled analyses, an open security finding, and expired privacy approval. Information is distributed across several sections. The workflow must not simply select the more favorable metric.

## Application and management summary

Coast Site requests local P-17 rollout. The management summary describes the test as successful and reports fewer transfers and faster answers for delivery-status questions.

The summary page states a high success rate. The exact calculation appears only in the later management analysis. The filename includes “final management view” and references ANA-P17-COAST-200-SUMMARY.

Site Management asks to place the application on the next committee agenda. It notes that a technical detail review is still in progress but predicts that it will not affect the outcome.

## Test design and version status

The local test ran for five weeks. The dashboard imported customer requests, internal follow-up questions, and automatically reopened records. Under the test plan, only genuine, fully completed customer requests belong in the binding metric.

The dossier includes two files that both claim final status. The management file uses 200 records. A later Quality audit attachment uses 184 valid records. No signed note resolves the version conflict.

The IDs are ANA-P17-COAST-200-SUMMARY and ANA-P17-COAST-184-AUDIT. Different sections describe each as authoritative. This conflict itself requires human review.

## Favorable management analysis

The management analysis counts 182 of 200 records as completed within 24 hours and reports 91%. It treats automatically reopened tickets as complete when the first response was sent on time.

The file contains no complete list of the 200 records. Eight internal training cases and several duplicate ticket imports are not labeled separately. The report does not explain why those records were included contrary to the test plan.

The positive figure cannot be treated as final verified without clarification. The word “final” in the filename does not resolve the conflict with the later audit attachment.

## Quality audit attachment

Quality removed eight training cases, five duplicate imports, and three automatically generated system tickets. The reviewed dataset contains 184 valid customer requests. Of those, 145 were resolved correctly within 24 hours. The audit attachment reports a final verified result of 79%.

The attachment also records 14 professionally incorrect initial routings and nine unnecessary transfers. Some cases have both characteristics. The audit ID is QA-P17-COAST-184, and the analysis ID is ANA-P17-COAST-184-AUDIT.

The attachment is dated later than the management file but does not yet have the Site Management signature. The workflow must therefore not silently declare either 91% or 79% the sole valid final value. It must state both figures, both IDs, and the unresolved status.

## Security and privacy

Security report SEC-P17-COAST-09 contains an open critical finding: exported diagnostic logs may include complete customer messages. A technical correction is planned, but closure evidence is missing.

Privacy approval DPA-P17-COAST-OLD expired six months before the current test and applies to an older system version. No updated retention plan is included. A note mentions 365 days but has neither approval nor a document ID.

These are additional blockers independent of the numerical conflict. Strong performance could not offset an open critical finding or invalid privacy approval.

## Open actions recorded by intake

Quality and Site Management have not agreed which analysis has binding final status. Both analysis files remain attached and neither has been withdrawn.

Information Security owns the critical finding and has not supplied closure evidence. Privacy must issue a current approval and an approved retention plan before the package can return to the committee.

The intake record contains no approval decision. It preserves the two analysis versions and assigns the unresolved actions to Quality, Information Security, Privacy, and Site Management.
